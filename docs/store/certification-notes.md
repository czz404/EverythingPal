## 1. 可直接粘贴的英文短版（Notes for certification）

```text
App type: this is a headless PowerToys Command Palette extension (MSIX, full-trust COM server).
It has no main window and no functional standalone UI by design; launching it from the Start menu
shows a small diagnostics dialog (PowerToys/Everything/es.exe checks and how to open Command
Palette). After installation it appears in Command Palette settings → Extensions and as an
"Everything Search" command.

PREREQUISITES
- Windows 11, or Windows 10 version 2004 (build 19041) or later (x64 or ARM64).
- Microsoft PowerToys with the Command Palette feature enabled (default hotkey: Win+Alt+Space).
- voidtools Everything 1.4 or 1.5a installed and running (this extension queries Everything's local
  index; it does not replace Everything). If Everything is not running, the extension shows an
  actionable message with "Start Everything" / "Download Everything" actions.

HOW TO TEST
1. Install PowerToys from the Store and enable Command Palette in PowerToys settings.
2. Install this app from the Store (no other setup is needed; the required es.exe is bundled).
3. Press Win+Alt+Space, type "Everything", select the "Everything Search" command (Chinese UI:
   "Everything 搜索"), then type a file or folder name that exists on the device (e.g. "winver").
   Results from the local Everything index are listed; Enter opens an item, the context menu can
   reveal it in Explorer, copy its path, or open it in Everything.
4. Optional home-screen inline results: Command Palette settings → Extensions → Everything Search →
   Fallback commands. Third-party fallback rows are disabled for global results by default (CmdPal
   platform behavior). Enable the rows and check "Include in the Global result", then type a file
   name on the Command Palette home screen to see up to 3 inline rows.
5. If Everything is not installed, step 3 still shows the actionable error state, which is the
   expected behavior; installing Everything and running it enables results.

CAPABILITIES
- runFullTrust: required to register and run the packaged out-of-process COM server
  (com:ExeServer / com:Class) that hosts the Command Palette extension. The app does not elevate
  and runs at normal user integrity.
- unvirtualizedResources (+ desktop6 FileSystemWriteVirtualization/RegistryWriteVirtualization
  disabled): the app writes its settings/logs to the real %LOCALAPPDATA%\EverythingPal and %TEMP%
  paths, and hands a temporary JSON export path to the bundled es.exe; MSIX write virtualization
  would redirect those paths. NOTE TO REVIEWER: if this capability cannot be approved, the app can
  be rebuilt without it; the two desktop6 declarations are the only reason it is present.
- No network capabilities are declared; the app makes no network requests.

EXTERNAL PROCESSES / DATA
- Bundled Tools\es.exe (MIT license, from github.com/voidtools/ES, notice in
  THIRD-PARTY-NOTICES.md) is executed per search to query the local Everything instance via
  Everything's local IPC and export JSON to a temp file. It is not downloaded at runtime.
- Everything.exe is NOT bundled. It is launched only when the user clicks "Start Everything".
- No telemetry, no data collection, no network. Settings and logs stay on the device.

The app icon is original artwork generated by this project's script; no third-party logos are used.
Support: https://github.com/czz404/EverythingPal/issues
```

## 3. 审核要点逐条解释（供内部答辩）

### 3.1 为什么看起来“没有界面 / 像 headless”？

这是 **Command Palette 扩展**，不是普通窗口应用：它的 UI 全部由 Command Palette 宿主呈现（命令页、列表、详情面板、设置页），扩展进程本身是后台 COM 服务器。安装后：

- Command Palette 设置 → **扩展** 中可见 **Everything Search**；
- 命令面板里输入 `Everything` 能找到「Everything 搜索」命令页；
- 无参启动（开始菜单点击 / `--about` / `--diagnostics`）会显示诊断对话框，说明这是 CmdPal 扩展、检查 PowerToys/Everything/es.exe 是否就绪，并提供「打开命令面板」等动作（**已实现**：`src/EverythingPal/Program.cs` 第 47–51 行 + `src/EverythingPal/Ui/LaunchDialog.cs`；提交前需按最终文案实测）。

> Microsoft 官方文档已明确支持把 Command Palette 扩展发布到 Store（见 [Publish to Microsoft Store](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/publish-extension-store)），并在其中给出“描述要写 integrates with the Windows Command Palette…”与“在认证备注写 PowerToys 前提 + 步骤”的要求；本文即按此准备。**但“headless 扩展能否稳定通过认证”本身没有可验证的公开样本（研究文档 §6 #16 标记为未验证）**，见 `README.md` 风险。

### 3.2 为什么需要 `runFullTrust`？

- 包清单通过 `com:ExeServer` + `com:Class` 注册**打包的 out-of-process COM server**，CmdPal 用 `-RegisterProcessAsComServer` 启动它并创建扩展实例；这需要 mediumIL 全信任。
- 全信任不等于提权：进程以当前用户身份运行，不请求管理员权限，不修改系统设置。
- 引用：[App capability declarations — Full trust permission level / Restricted capabilities](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/app-capability-declarations)。

### 3.3 为什么需要 `unvirtualizedResources` + `desktop6:*WriteVirtualization=disabled`？

当前清单开启了 `desktop6:FileSystemWriteVirtualization=disabled` 与 `desktop6:RegistryWriteVirtualization=disabled`，因此必须声明 `unvirtualizedResources`。理由是：

1. 设置文件写到 `%LOCALAPPDATA%\EverythingPal\settings.json`、日志写到 `%LOCALAPPDATA%\EverythingPal\Logs\extension.log` 与 `%TEMP%\EverythingPal.log`（用户/支持人员需要能直接看到真实路径）；
2. 每次搜索把临时 JSON 导出文件路径传给内置 `es.exe`（外部进程），MSIX 文件/注册表写虚拟化会重定向写入路径，导致 `es.exe` 读取不到导出文件、或日志落到 virtualized 存储里。

**风险与建议（重要）**：Microsoft 文档说明 `unvirtualizedResources` 主要面向 Microsoft 及合作伙伴发行的游戏、以及 external location 打包应用，**并不面向一般场景**，审核时很可能被要求说明或拒绝（研究文档 D.10 / E.13 #4）。两条路：

- **保留**：用上面的理由回答 Submission options，并在认证备注中主动说明（本文已提供）。
- **移除**（研究文档建议，需产品验证）：去掉 `<desktop6:FileSystemWriteVirtualization>` / `<desktop6:RegistryWriteVirtualization>` 与 `unvirtualizedResources`，回归测试设置持久化、日志、`es.exe` 导出是否仍正常。若可行，认证风险显著降低。**最终取舍由 Lead/用户决定；不在本任务写权限内（不能改 manifest）。**

### 3.4 外部进程与网络

| 行为 | 说明 | 网络 |
| --- | --- | --- |
| 每次搜索启动 `Tools\es.exe` | 包内自带（MIT）；`Process.Start`，参数含 `-export-json <临时文件>`；读取 JSON 后删除临时文件；超时 1500 ms | 无（与本地 Everything IPC） |
| 点击「启动 Everything」 | 仅当用户点击时，启动用户已安装的 Everything.exe（先定位安装路径） | 无 |
| 点击「下载 Everything」 | 调用 `shell` 打开 voidtools 下载页（浏览器/商店网络行为） | 用户主动、由系统浏览器发起 |
| 打开 CmdPal 设置/命令面板 | 用户点击「打开命令面板」时通过 `shell:AppsFolder` 启动 | 无 |

- 包清单**没有** `internetClient` / `privateNetworkClientServer` 能力；应用自身无 HTTP 客户端、无遥测。
- 内置 `es.exe` 通过 Everything 的**本地 IPC** 通信（非网络）；Everything 本体由用户安装。
- 引用：[Everything CLI / ES 项目](https://github.com/voidtools/ES)、[Everything 官网](https://www.voidtools.com/)。

### 3.5 第三方组件与许可

- `es.exe`：来自 voidtools/ES，**MIT**；包内 `THIRD-PARTY-NOTICES.md` 保留版权与许可全文。
- Everything 本体：**不随包分发**，由用户自行安装；本应用仅查询其索引。
- 应用图标：原创（`scripts/generate-icons.py`），无 voidtools/Microsoft 商标。
- 待确认风险：voidtools 是否允许把 `es.exe` **再分发**进商业 Store 包（MIT 文本允许，但官方 FAQ/条款需确认；研究文档标记未验证）。

### 3.6 数据与隐私

- 不收集、不传输任何个人数据；无遥测/广告/崩溃 SDK；查询不写日志（只记录状态与条数）。
- 本地保存：`%LOCALAPPDATA%\EverythingPal\settings.json`、`%LOCALAPPDATA%\EverythingPal\Logs\extension.log`、`%TEMP%\EverythingPal.log`；错误日志可能含本机文件路径，仅本地排障用。
- 详见 [privacy-policy.md](privacy-policy.md)（需托管为公开 URL）。

### 3.7 可能被问到的问题（Q&A）

| 审核问题 | 回答 |
| --- | --- |
| 为什么安装后没有可执行窗口？ | 这是 Command Palette 扩展，UI 由 CmdPal 宿主呈现；扩展进程是后台 COM 服务器。见 §3.1 与测试步骤。 |
| 为什么需要 full trust？ | 打包 out-of-process COM server 托管 CmdPal 扩展所必需，非提权。见 §3.2。 |
| 为什么要关闭写虚拟化？ | 让设置/日志落在真实路径，并让内置 es.exe 读取临时导出文件。见 §3.3。 |
| 应用会读取我的文件内容吗？ | 不会读取文件内容；只显示 Everything 索引返回的文件名/路径/大小/时间等元数据。 |
| 会联网吗？ | 不会；包未声明网络能力，无网络调用。用户主动点击下载链接时由系统浏览器打开网站。 |
| 为什么搜索结果为空？ | 需要 Everything 正在运行；若未安装/未运行，界面会给出启动/下载提示。 |
| 为什么主页没有内联结果？ | CmdPal 默认不把第三方 fallback 加入全局结果；需在 CmdPal 设置中启用（见测试步骤 4）。 |
